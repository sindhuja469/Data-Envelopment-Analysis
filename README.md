# Data-Envelopment-Analysis
# Efficiency Benchmarking of Controlled-Environment Horticulture Operations Using DEA (with Spoilage as an Undesirable Output)

Data Envelopment Analysis (DEA) study of U.S. greenhouse and hydroponic vegetable operations that explicitly models postharvest spoilage as an **undesirable output** — rather than ignoring it, as most efficiency benchmarking studies do.

## Motivation

Standard DEA efficiency studies of agricultural operations score performance on inputs (energy, water, labor, land, capital) against desirable outputs (yield, revenue) alone. That leaves a blind spot: an operation can look fully efficient while quietly spoiling a large share of what it grows. This project treats spoilage rate as a second class of output that a well-run operation should minimize, not something the model is indifferent to.


## Model specification

- **Method:** VRS (variable returns to scale), output-oriented DEA
- **Package:** [`deaR`](https://cran.r-project.org/package=deaR), `model_basic(orientation = "oo", rts = "vrs")`
- **Inputs (5):** energy (kWh), water (L), labor (hours), area (m²), capital (USD)
- **Desirable outputs (2):** yield (kg), revenue (USD)
- **Undesirable output (1):** spoilage rate (proportion of product lost), modeled via the Seiford & Zhu (2002) monotone translation

## Known modeling limitation

Treating the translated spoilage rate as an additional *output* fed into an output-oriented VRS model has a structural consequence: adding an output dimension can only weakly *improve* (never worsen) a DMU's efficiency score. In practice this means an operation that is efficient in the baseline (desirable-outputs-only) model is mathematically guaranteed to remain efficient once spoilage is added — so the model cannot surface operations that "look efficient until you count their waste," which was the original goal.

Two paths are being evaluated to fix this:
1. Model spoilage as an **input** rather than a translated output.
2. Use a genuine **directional distance function** (`deaR::modelddf()`), which expands desirable outputs and contracts the undesirable one simultaneously, rather than adding a dimension that can only help.

This limitation is treated as a documented methods finding, not a bug to hide — see `docs/methods_notes.md`.

## Data

- **Primary intended source:** USDA NASS Census of Horticultural Specialties, via the [Quick Stats API](https://quickstats.nass.usda.gov/api). NASS reports area under structure, sales, and production expenses at **state level**, but not energy use or spoilage rate directly.
- **Constraint:** farm-level microdata is confidentiality-protected under 7 U.S.C. § 2204(g), capping the public baseline at state-level aggregation.
- **Current dataset:** a calibrated **simulated dataset** (120 greenhouse/hydroponic operations; `set.seed(42)`) stands in for real data while the DEA pipeline is built and validated. Desirable outputs and spoilage are both generated from a latent per-operation productivity factor, so the simulated frontier reflects a genuine input–output relationship rather than independent random draws.

## Running it

```r
install.packages(c("deaR", "Benchmarking", "dplyr", "tidyr", "ggplot2"))
source("R/dea_greenhouse_spoilage.R")
```

Outputs (efficiency scores, slack analysis, two diagnostic plots) are written to `dea_outputs/`, which is created automatically if it doesn't exist.
